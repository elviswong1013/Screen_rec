# 004 - Screen_rec：录制状态可查询与开始前告知（M19b）

## 1. 背景与目标

M19a 解决了文件名/manifest 的窗口标题泄漏。录制进行中仍缺少状态可查询性：主窗关闭后只能依赖 Windows 捕获边框（可被系统设置关闭），托盘 tooltip/菜单是静态的；开始录制前也没有目标/音源/输出摘要与告知提示。M19b 让用户可以通过托盘 tooltip、菜单和主窗标题**查询**当前是否在录制、路数和收尾状态，并在主窗开始入口展示简短告知。

**限制说明**：tooltip 需要悬停、菜单需要打开、主窗标题在主窗隐藏时不可见；本切片不承诺“关闭主窗后始终可见的指示器”，也不据此关闭 release-checklist G2-01 的完整要求。置顶浮窗留待后续。

## 2. 非目标（本切片明确不做）

- 置顶悬浮窗、红点图标资源、任务栏 overlay icon。
- 托盘“开始”路径的二次确认/告知（仅状态指示；托盘启动语义不变）。
- 退出确认、旧会话 UI 标题脱敏、日志/错误串脱敏、About/许可证、CSP/IPC、安装包/签名。
- 零音源“纯画面”录制（当前 UI/后端均拒绝零音源启动；本切片不新增该能力）。
- 任何法律合规结论；文案只是产品提示。

## 3. 用户故事

- US-1：我关闭主窗后，可从托盘 tooltip/菜单查询正在录制及路数，并能停止。
- US-2：我在录制中关闭主窗时，得到一次明确提示“录制仍在继续”，而不是静默消失；再次关闭不重复弹框。
- US-3：我在主窗开始录制前，能看到将录制的目标、音源与输出；含麦克风/系统/端点声音时，首次使用前需要一次确认。
- US-4：我可以勾选“不再显示此提示”，之后主窗开始不必重复确认；我也能取消该勾选。

## 4. 验收标准（AC）

- **AC-1（状态可查询）**：录制/收尾期间，托盘 tooltip 反映按 route id 统计的 recording/stopping 数量（混合状态同时显示，例如 `录制中 (1 路) · 收尾中 (1 路)`）；无活动时恢复 `Screen_rec`；菜单开始/停止 enabled 随状态变化；主窗可见时标题反映状态。**不新增图标资源**；不承诺 tooltip 在未悬停时可见。
- **AC-2（关闭主窗）**：录制中首次关闭主窗，先 `prevent_close`，后台显示一次原生提示“录制仍在继续；可从托盘停止或重新打开窗口”，确认后隐藏；提示进行中的重复关闭不再弹框；本进程后续关闭静默隐藏；空闲关闭静默隐藏。不得在窗口事件回调内同步弹框/等待。
- **AC-3（主窗开始前摘要/告知）**：开始栏可展开，显示目标、音源标签、输出目录与格式；音源包含麦克风、系统或 render_endpoint 且 `recording_notice_ack=false` 时，第一次点“开始”只展开并显示告知，第二次确认才启动；仅应用音源或 `ack=true` 时一次点击启动；零音源仍按原逻辑拒绝。区域选区确认仅是选区交付，不算开始确认；纯录音摘要显示 WAV，不显示画布/帧率；区域显示最终选区尺寸。
- **AC-4（设置/验证）**：`Settings.recording_notice_ack` 默认 false、缺字段 false、坏类型只降级本字段；开始栏勾选/取消会保存全部其他设置；设置页保存其他字段时保留 ack；保存失败不得伪装成功；勾选本身不启动。托盘/关闭提示的纯函数与 UI 告知有自动化测试；完整 GUI/托盘交互指定 L3 人工签核。

## 5. 约束

- Windows 10 2004+/11 x64；不新增依赖、不联网；不改录制/编码/同步/恢复语义。
- 托盘状态固定使用后端 1s 轮询（初始化立即刷新、变化才应用），读取状态后释放锁再调用 Tauri UI API；不持路由锁等待主线程。
- 关闭提示：`prevent_close` 与原子认领在回调内完成；弹框/隐藏走后台，失败记录并保留窗口，不重复消耗“首次提示”标志。
- 告知只覆盖主窗开始入口；托盘开始、区域 overlay 确认均不视为开始确认。
- 现有 UI runner 的直接启动流程需同步；不得删除/弱化零音源、终态竞态等既有断言。
