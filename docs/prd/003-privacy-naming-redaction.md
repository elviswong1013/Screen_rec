## 1. 背景与目标

当前窗口录制会把窗口标题写入成品文件名和 manifest `identity.name`；标题可能包含文档名、聊天对象、网页标题等个人信息。M19a 的目标是把**默认行为**改为通用目标名，同时保留显式选择旧行为的开关，并保证旧 manifest 仍可恢复。

本文件是对**已实现代码** `d42f9c5` 的正式变更请求：实现先于本批准记录存在；本文件不回溯声称“先批准后实现”，批准日期以用户实际批准日为准。

## 2. 非目标（本切片明确不做）

- 托盘持续录制指示、开始前摘要/告知、关闭主窗提示、退出确认。
- 日志/错误串脱敏、About/许可证入口、CSP/IPC 收紧、置顶浮窗。
- 旧会话恢复列表的标题显示脱敏（仅保证新成品名/新 manifest/恢复成品名）。
- 安装包重建、签名、法律/专利清权、AVC/AAC 许可。

## 3. 用户故事

- US-1：作为用户，我默认录窗口时，成品名和会话清单不应出现窗口标题，避免把文档名/聊天对象带到文件名。
- US-2：作为需要可读文件名的用户，我可以在设置中显式开启“包含窗口标题”，并看到隐私提示。
- US-3：作为崩溃恢复用户，我的旧 v1 会话仍能扫描、收尾、幂等复用；恢复出的新成品默认不携带旧标题。

## 4. 验收标准（AC）

- **AC-1（默认脱敏）**：设置默认 `include_window_title_in_filename=false` 时，Window 目标名为通用 `Window {seq}`（不含窗口标题）；成品文件名使用 `sanitize(target_name)`，manifest `identity.name` 保存**未 sanitize 的 target_name**（false 为通用名；true 为原样窗口标题）。设置为 `true` 时回退旧行为：文件名使用 sanitize 后的标题，manifest 保存原样标题。
- **AC-2（设置）**：字段缺省为 false；字符串/数字/null/对象/数组等坏类型只降级本字段，不重置其他设置；设置页提供复选框、默认关闭、保存/重载一致。mock 默认 false；mock 的 `setSettings` 合并仅用于前端测试，不构成“后端保留未知字段”的契约（后端以完整 Settings 替换）。
- **AC-3（兼容）**：旧 v1 manifest（含标题/绝对路径）仍可解析、扫描、收尾、幂等复用；旧成品文件不重命名，已有有效 `final_path` 原样复用（即使名称含标题），旧 manifest 的 `identity.name` 不追溯脱敏。仅对需要**新生成的非 WAV 成品**，默认使用 `{timestamp}_recovered-{sanitize(route_id)}`；`true` 时保留旧恢复命名。
- **AC-4（验证）**：工作区测试、隐私命名测试、设置 runner、恢复 L2 回归通过；不要求长同步/完整 GUI/安装包；每项变更/测试可追溯到 REQ-1..5。

## 5. 约束

- Windows 10 2004+/11 x64；不新增依赖、不联网、不改 FFmpeg sidecar 语义。
- 旧 public API 保持“默认 true”以兼容既有测试/调用；命令层显式传入设置值。
- 旧成品/旧会话不追溯改名；旧会话 UI 标题显示脱敏留待后续切片。
- 本切片不改变录制的编码、音轨、同步、崩溃恢复预算。
