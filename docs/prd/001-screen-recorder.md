## 1. 背景与目标

用户需要一个 Windows 桌面工具，支持截图、录屏、录音。核心诉求超出普通录屏软件：

1. **按应用音轨隔离**：同时播放两个视频时，只录制其中一个（窗口）时，产出文件里只有该应用对应的音轨，不混入其它应用的声音。
2. **多路同时录制**：支持同时录制 2 个及以上窗口/应用，各自产生独立文件，音视频互不干扰。

可行性研究结论（5 路调研，详见研究文档）：
- 现成免费工具均无法完整满足：OBS 最接近（「应用音频捕获」可做到按应用隔离；但单实例只有一个录制输出，多路并发需多实例 workaround；音频隔离粒度为进程树，浏览器多标签不可分）；Cap 不支持按应用音频与多路并发；其余候选仓库（Flutter 插件/Android 示例/Chrome 扩展/Web SaaS）平台不符。
- **自研技术可行**：Windows.Graphics.Capture（WGC，窗口/显示器捕获）+ WASAPI 进程环回（按进程树音频捕获）+ 多轨封装（MKV/FFmpeg 或 Media Foundation），均为系统原生能力且许可干净。

**已确认决策（2026-10-15）**：
- 路线：自研桌面程序。
- 技术栈：Rust + Tauri。
- 多路输出：每路独立文件；支持录制结束后合并为单个多轨 MKV。
- 音轨输出：默认「仅目标应用」（隔离）；另提供「全音轨」模式（所有音源各为独立轨道，见 AC-4）。
- 目标环境：Windows 10 2004+ 与 Windows 11（x64）。

## 2. 非目标（v1 明确不做）

- 视频编辑/剪辑/字幕/标注（合并工具除外，见 AC-5）。
- 直播推流、云上传/分享。
- 摄像头采集与画中画。
- macOS / Linux 支持。
- 浏览器内多标签 / 同一进程内多路音频的拆分（API 层面不可行，见约束）。
- 单文件内多视频轨的「原生录制」（采用独立文件 + 事后合并方案）。
- HDR 录制（v1 以 SDR 为准）。
- 虚拟声卡的分发与自动安装（文档可给出替代指引）。

## 3. 用户故事

- US-1 截图：我可以截取整个显示器、指定窗口或屏幕区域，保存为 PNG。
- US-2 隔音录制：我选择某个窗口开始录制，即使其它应用正在播放声音，录下来的文件里也只有该窗口应用的音频。
- US-3 多路录制：我可以选择 2 个及以上窗口同时开录，每个窗口一个独立文件，各自只含对应应用的音轨；任一路可单独停止。
- US-4 合并：录制结束后，我可以把多路文件合并成一个 MKV（各路音视频保留为独立轨道），流拷贝、不重编码。
- US-5 纯录音：我可以只录音（麦克风 / 系统音频 / 指定应用），不录屏。
- US-6 麦克风音轨：录制时可选启用麦克风，作为文件内一条独立音轨（不与应用音轨混在一起）。
- US-7 目标选择：我可以看到可捕获的窗口/应用列表（含应用名与进程名）并刷新。
- US-8 环境适配：在不支持按应用音频的系统上，程序明确告知并降级，不静默失败。
- US-9 全音轨输出：录制时我可以选择输出全音轨——所有音源（目标应用 / 系统音频 / 麦克风 / 其它所选应用）各自成为独立轨道，互不混音；例如同时录两个视频时，一份文件里可同时保留 A、B 两条独立音轨供后期选择。

## 4. 验收标准（AC）

**AC-1 截图**
- 支持：整个显示器（多显示器可选）、指定窗口、屏幕矩形区域；输出 PNG。
- Given 双显示器：When 选择显示器 2 截图 Then 图片为该显示器完整画面（DPI 缩放正确）。
- Given 选中某窗口：When 截图 Then 图片为该窗口内容（被其它窗口遮挡时仍正确）。

**AC-2 按窗口录制且音轨隔离（核心）**
- Given 应用 A 与 B 同时播放不同音频（可区分信号）；When 只选择 A 的窗口录制并停止；Then 产物视频仅含 A 窗口画面，音轨不含 B 的音频（谱分析无 B 信号分量）。
- 说明：隔离粒度为进程树（系统 API 限制）——同一应用的多窗口共享同一条音轨；同进程内多路音频不可分。

**AC-3 多路同时录制（核心）**
- 支持同时录制 ≥2 路（窗口/显示器可混合）；每路生成独立文件，文件内为该路目标画面 + 仅该目标的音轨（逐路按 AC-2 方式验证）。
- 各路可独立停止；全部停止后每路文件均完整可播。
- Given 已选 3 路：When 停止第 2 路 Then 第 1、3 路不受影响继续录制。

**AC-4 音轨组织与输出模式**
- 每路录制的音轨输出可选：
  - 「隔离」默认模式：1 条音轨 = 该目标应用音频；若启用麦克风，追加 1 条独立音轨（不混音）。
  - 「全音轨」模式：输出所有已捕获音源的独立音轨、互不混音。音源集合 = 目标应用 + 系统音频 +（启用时的）麦克风 + 用户额外选择的应用（提供「全选」）。
- Given 隔离模式 + 启用麦克风：When 检查产物 Then 可见 2 条可切换音轨（应用音轨 / 麦克风音轨）。
- Given 全音轨模式 + 应用 A、B 同时播放不同音频 + 启用麦克风，录制 A 的窗口：Then 文件含 ≥3 条独立音轨——目标应用轨（仅 A 信号）、系统音频轨（A+B 混合，设计语义如此）、麦克风轨；各轨可分别切换。

**AC-5 合并**
- 选择 ≥2 个已完成录制文件，输出单个 MKV；各路的视频流与音频流以流拷贝方式保留为独立轨道（不重编码）。
- Given 2 个 MKV 输入：When 执行合并 Then 输出文件可正常播放，轨道清单与输入一致（2 视频 + 2 音频）。
- 形态已确认（2026-10-15）：多视频轨并存、流拷贝、不重编码，播放器可切轨。

**AC-6 纯录音**
- 支持选择 1..N 个来源（麦克风 / 系统音频 / 指定应用），每个来源产出独立音频文件（默认 WAV，48kHz）。
- Given 选择「系统音频」录音 30 秒：When 停止 Then 产出音频文件时长 ≈30s 且包含录制的系统声音。

**AC-7 目标枚举**
- 可列出：显示器、可见窗口（应用名 / 进程名 / 标题），支持刷新。
- Given 打开/关闭应用 L：When 刷新 Then L 出现在/移出列表（≤2s）。

**AC-8 环境探测与降级**
- 启动时探测 process loopback 可用性；不可用时（如 Win10 <2004）界面明确说明，禁用按应用音频相关功能并给出替代提示，其余功能（截图、麦克风录音、设备环回）可用。

**AC-9 稳定性与同步**
- 同时录制 2 路 1080p30 视频 ≥10 分钟：无崩溃；每路音画偏差 ≤150ms 且不随时间累积；正常停止后文件均完整可播。
- 具体测量方式在 SDD 测试计划中细化。

**AC-10 异常恢复**
- 录制中强制结束进程（模拟崩溃）：已写入磁盘的内容仍可读取/播放（MKV 分段机制）；允许丢失末尾未刷盘数据。

## 5. 约束与前提

- 平台：Windows 10 2004 (19041)+ / Windows 11，x64；ARM64 未定（开放问题 4）。
- 技术栈：Rust + Tauri（已定）；捕获/编码/封装的具体组件选型在 SDD 决定。
- 许可：依赖优先 MIT/Apache-2.0/LGPL；避免 GPL 传染（若用 FFmpeg 须 LGPL 配置、不启用 GPL 组件；或改用 Media Foundation）。
- 音频隔离粒度为进程树；同一进程内多路音频不可分；个别应用（如 MS Teams、部分反作弊游戏语音）可能无法捕获 → 需明确错误提示与文档说明。
- 「全音轨」模式中每个应用音源同样按进程树捕获；同一应用的多窗口共享一条音轨；系统音频轨为整机混合（包含已单独捕获的应用声音）。
- 时基：QPC 统一；音频 48kHz float 采集；静音期补静音帧防时间戳跳变。
- 输出容器：MKV 默认（多轨友好）；是否额外提供 MP4 见开放问题 8。
- 资源目标：2 路 1080p30 同时录制在近 5 年主流 4 核以上机器上不应造成被录应用明显卡顿（优先硬件编码）；具体指标 SDD 定。

## 6. 开放问题

1. （已确认 2026-10-15）合并形态：多视频轨并存、流拷贝、不重编码。
2. 是否需要摄像头画中画？（当前非目标）
3. HDR 录制是否列入 v1.x？（当前 SDR）
4. ARM64 Windows 支持？
5. UI 形态细节：托盘、全局热键、录制中悬浮控制条？
6. 纯录音默认格式：WAV 还是 FLAC？
7. 是否公开开源该仓库？（影响依赖选择与文档）
8. 是否需要 MP4 输出（单轨场景）？
9. 固定 48kHz 立体声采集是否可接受？还是需跟随设备采样率？
10. 「全音轨」模式：是否需要在录制开始时自动发现所有正在发声的应用并各建一条轨？当前设计为手动添加音源 + 「全选」（更可控）。
