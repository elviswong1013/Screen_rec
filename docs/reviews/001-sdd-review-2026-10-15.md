## 2. 圆桌：有条件批准（P0 修订清单）

五项决策裁决：①sidecar 有条件保留（有条件：精确构建实测/真实兜底/吞吐达标/可取消 I/O）；②分段保留但重写保证（关键帧/损失上界/幂等恢复/全轨 concat；删除无条件 ≤10s）；③同步保留组件重写时间轴契约（源时间戳/唯一调度者/阶跃校正/全轨指标）；④隔离必须修订（有界应用根）；⑤测试保留分层补齐准入（无设备集成/交互 L2/故障注入/自动同步分析/硬件矩阵/发版签核）。

分歧裁决：
- 进程树：统一为「应用级身份解析 + 默认后代树 + 有界提升 + 禁止跨系统宿主（explorer.exe/svchost.exe/ApplicationFrameHost.exe/RuntimeBroker.exe/sihost.exe）+ PID+创建时间 + 共享音轨告知」。
- `h264_mf`：不靠投票——按发行构建实测四层（源码编入？初始化？NV12/关键帧/并发/吞吐？）；不得作无条件兜底；H.264 为硬要求时 VP8/VP9 非等价兜底。
- 收尾：删除无条件 ≤10s；改为「停止采集独立响应 + 后台收尾（进度/重试）」。
- resize：v1 固定输出画布（等比缩放+黑边；段间参数恒定；异构轨合并允许）。
- 启动屏障：不得等全部管道连接；分离「采集就绪/管道建立/编码器探测/输出开始」，统一时间轴并发供数。
- 缓冲：不照搬 `-thread_queue_size 512`（512 帧 NV12 ≈1.5GiB/路）；队列按字节+时间双重限界；管道缓冲 4–16MiB 仅实测起点。
- 恢复：不采纳「主进程死后 ffmpeg 必 EOF 自愈」为保证；v1 用 Job 对象终止 sidecar（损失当前段换可预测性）；EOF 自愈仅作验证后优化。
- 权限：不预设 loopback 弹 consent；麦克风隐私/WGC/音频激活分别定义；「激活成功但无信号」不得直接归因权限或受保护音频。

Spike 验收标准（前置门禁）：S2（编码器能力矩阵+许可，最先）→ S1（管道/转换/启动/启动死锁/阻塞取消）→ S3（真实音频隔离：目标存在/泄漏达标/浏览器多窗口/最低 OS）→ S5（分段/崩溃矩阵：5s+δ 损失、幂等恢复、边界无爆音）→ S6（端到端内容同步：≤150ms 不累积，含背压注入与 concat 后）。

残余风险（定性）：编码/并发失败（未知，S2）、特殊应用音频归属（中高）、极端背压阶跃错位（中高）、AAC/时间戳接缝（中）、磁盘/收尾（中）、多视频轨播放器支持（中）、电源/驱动故障边界（未知）、许可交付（未知）。

需 Gate 2 用户授权的产品取舍：无硬件编码器行为 / 是否允许非 H.264 / 最低 OS 与并发承诺 / 固定画布 resize / 恢复损失边界 / 后台收尾。
