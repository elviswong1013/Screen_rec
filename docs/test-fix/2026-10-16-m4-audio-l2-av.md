## 7. 取证结论（2026-10-16 更新；根因判定）

### 7.1 崩溃站点（在线符号化，方法：`link.exe /MAP` + 反汇编；dbghelp 对 Rust PDB 不可用）

- WER 故障偏移在同一构建内**完全恒定**：原构建 `0xf41a82`；取证构建 `0xF3F03D`（另一轮 `0xF3E7CD`，同函数区）。
- MAP 解析：`0xF3F03D` 落在 `windows::Graphics::Capture::GraphicsCaptureSession::IsSupported`（windows 0.62.2 生成代码；经 `windows_core::imp::FactoryCache` 静态分发）。
- 反汇编（dumpbin）：故障指令 `mov rax,[rsp+30h]; mov rax,[rax+30h]` —— 从栈槽取指针后读 `+0x30` 字段；`fault_addr=0x7FFB7302A0D8` ⇒ 基指针 `0x7FFB7302A0A8`（堆区，已释放/未映射）。
- 线性栈扫描（VEH 内）命中：`FactoryCache<GraphicsCaptureSession, IGraphicsCaptureSessionStatics>::call::{{closure}}`、`AtomicPtr::<c_void>::load`、`WGC 捕获线程帧`（`GraphicsCaptureApi::new::<wgc::FrameForwarder>`、`start_free_threaded` 闭包）、`windows_strings`（`HSTRING::from_wide_iter` / `HStringHeader::free` / `HSTRING::drop`）、`IUnknown::drop`。
- 崩溃线程 = **新建的 WGC 捕获线程**（`tid` 恒定于单次崩溃；栈含 capture-thread 帧），崩溃发生在 `start_audio_route → wgc::start_window_stream → windows-capture 会话初始化` 早期。

### 7.2 触发规律（跨 3 份历史日志 + 本轮 ≥8 次复跑）

- 单用例独跑：**不崩**。任意"含 1 个 route 用例"的进程：第 1 个 WGC 会话必成功。
- **进程内第 2 个 WGC 会话**（multitrack/bp 中后启动者）→ `GraphicsCaptureSession::IsSupported()` 处 AV；并行/串行两模式一致；与用例断言成败无关。
- 崩溃非 100% 概率（观测 ≈4/7 全量轮次），与 windows-capture 上游 issue 描述「reproduces all the time / happens not always」一致。

### 7.3 上游对照（决定性）

- **windows-capture issue #124**（2025-02 报）：第二次 `start_free_threaded` → `STATUS_ACCESS_VIOLATION`；维护者诊断「WinRT is already initialized, and it shouldn't reinitialize it」；讨论「thread affinity / MTA 生命周期」；关联修复 **PR #133 "fix RoInitialize"**（2025-05 合并）：加 `CoIncrementMTAUsage` 保持**长寿命 MTA**（原始实现为 OnceLock 永不释放）。
- **windows-rs issue #1169** 权威建议：*"A long-lived MTA is the only recommended approach."*
- 本仓锁定 **windows-capture 2.0.1**：`src/winrt.rs` 为「每会话 `CoIncrementMTAUsage` → `RoInitialize(MTA)`；Drop 时 `RoUninitialize` + `CoDecrementMTAUsage`」——**MTA 引用计数可归零**，COM/WinRT 运行时拆解 MTA；而 windows-rs `FactoryCache` 是**进程级静态**且缓存指针靠 leak 假定存活 ⇒ 后续会话取到失效工厂指针 → 恰在我们观测的 `IsSupported`/`FactoryCache` 指令处 AV。
- 上游 main 分支今日仍为「每会话递增/递减」形态（`winrt_commits`：083cbd3e 2025-12-26 "Add a safe wrapper around windows rt api initialization"）——即该缺陷类在 2.0.1 未消除。

### 7.4 假设判定

| 假设 | 判定 | 依据 |
|---|---|---|
| H1 wasapi 流式路径残留导致下次 route 启动 AV（COM 生命周期） | **部分成立（机制收窄为 MTA 生命周期）**：audio 侧不是坏指针持有者；崩溃全部在 windows-capture/WinRT 缓存路径 | §7.1–7.3 |
| H2 harness（ProbeWindow/ffplay） | 排除：崩溃线程为 WGC 捕获线程，栈无 harness 帧 | 栈扫描 |
| H3 sr-pipeline 线程/管道竞态 | 排除：崩溃在 `start_stream` 内部、Windows 侧生成代码 | §7.1 |
| H4 wasapi 线程 COM 未配对 CoUninitialize | 排除为主因（不直接构成坏指针）；但其线程 MTA 进出会加速 MTA 拆解时机 | §7.3 |

**根因（判定）**：windows-capture 2.0.1 的会话级 MTA 递增/递减使进程 MTA 可被拆解，而 windows-rs 进程级 FactoryCache 缓存的前序 WinRT 工厂指针随之失效；下一次会话（M4 用例中为第 2 个 route 用例）在 `GraphicsCaptureSession::IsSupported` 路径解引用失效指针 → AV。

### 7.5 修复（假设 H1→H-L 单点假设）

- 修法：`crates/sr-capture/src/wgc.rs` 增加进程级 MTA 保活（`CoIncrementMTAUsage` 一次性、永不递减；raw FFI `combase.dll`，不引入新依赖），在 `start_stream()`（窗口/显示器两入口共用）内、任何会话来启动前执行。
- 依据：对齐 windows-rs #1169 建议与上游 PR #133 原始方案（长寿命 MTA）；单个空 MTA 常驻成本可忽略（一个 cookie）。
- 改动文件：仅 `crates/sr-capture/src/wgc.rs`（生产侧）。测试文件仅含临时取证代码（验收前删除）；断言语义零改动。

### 9.2 丛生 ffplay（PID 48904/63040）泄漏路径 —— 次生效应（H6 判定）

- 机制：`KillTreeOnDrop` 仅在测试函数正常返回/panic 展开时执行；进程级 AV 为**非展开式终止**（无 unwind、Drop 不运行）⇒ 崩溃当次 run 存活的 ffplay（含 cmd 包装树）整体泄漏。「丛生 ffplay」与 AV 同链（AV→漏杀），非 AV 之因。
- 反证（依据通道报告与日志时间）：通道报告为「先清理丛生、再复跑」，而清理后的修复前复跑（12:12/12:13 两轮）仍以同一签名崩溃 ⇒ 丛生非 AV 之因；修复后 11 个全量轮次（含 6 次断言失败轮，panic 路径 Drop 正常清理）抽查 0 残留、0 AV ⇒ 泄漏随 AV 消失。
- 次生影响（仍应清理的原因）：残留 ffplay 持续放音 → (a) 抬高负载/音频引擎占用（与 §9.5 FFT 目标电平波动相关）；(b) 跨轮混入无关音调污染 FFT 测量。
- 防误归因：本机并行会话（`%TEMP%\opencode\sr-m5-red-scratch`，M5 红测试，自带 tools/ffmpeg 副本）也用 ffplay 且其进程 12:48–12:59 多次自身 AV；现场核查 ffplay 归属须用 `Win32_Process.CommandLine/ParentProcessId`（本轮实测 PID 35752 即属彼方）。操作建议：每轮开跑前按命令行归属清扫；**不在 harness 内自动跨会话杀进程**（可能误杀他方在跑用例）。
